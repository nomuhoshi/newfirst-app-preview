## 清单 A：真实收信、真实同步（设计bot 或老大）

两端必须是**隔离的**：两个不同的浏览器（例如 Safari + Chrome），或两个独立的浏览器配置，或两台设备。不要用同一浏览器的两个普通标签页。
每一步记：浏览器和版本、时间、结果（通过 / 失败 + 现象）。

**真实收信**（单独登记）
1. 端 1 打开预览，进「我的」→「邮箱登录 / 注册」，填测试邮箱，点「发送验证码」，记时间 T0。
2. 记页面结果：成功进入“输入验证码”，还是出现哪条提示（原文照抄，遮住邮箱）。
3. 记收到邮件的时间 T1，收信耗时 = T1 − T0；是否进垃圾箱。
4. 用验证码完成登录：成功 / 失败（提示原文）。

**真实同步**（单独登记）
1. 端 1 登录前：做完 U1L1（4 道题），记「我的」页 XP（4 题都一次答对应为 50）、已完成关卡（1/34）。
2. 端 1 登录（同上收信步骤）。出现游客进度选择时选「安全合并到账号」。等「测试入口信息」的同步状态变成「已同步 ✓」。记 XP 和已完成关卡（应与第 1 步一致）。
3. 端 2 打开预览，**登录前先确认**：XP 0、已完成 0/34（看不到端 1 的游客进度）。
4. 端 2 登录同一邮箱（如有游客选择，端 2 没有游客进度一般不会出现）。记 XP、已完成关卡：应与端 1 第 2 步一致。
5. 端 2 刷新页面：XP、关卡不变（不增加）。
6. 端 2 退出登录，再用同一邮箱重新登录：XP、关卡不变。
7. 端 1 刷新：XP、关卡不变。
8. 两端都退出：提示没有英文原文；「测试入口信息」的「最近确认同步」显示「—」。
9. 任一步 XP 变大 = 重复加分，记为失败并截图。

## 清单 B：iPhone 真机（Safari、主屏幕 App 各跑一次，分开记录）

记机型、iOS 版本。主屏幕 App：Safari → 分享 →「添加到主屏幕」，从图标打开（它和 Safari 的数据是分开的）。
1. 验证码登录：按清单 A「真实收信」1–4。
2. 做题：U1L1 第 1 题（选输出，代码 `print("欢迎光临！")`），选「欢迎光临！」，点「检查」。应显示答对；点「继续」进入第 2 题。
3. Python 真的在跑：第 2 步点「检查」后，展开下方「运行结果」，应显示 `欢迎光临！`（第一次可能显示“运行中…”几秒，Python 正在加载）。
4. 离线重开：
   - 先联网完整打开一次，等「运行结果」能出结果；再刷新一次（让离线缓存接管）。
   - 开飞行模式，彻底关掉页面 / App，再打开：**应能进地图、能做点选题**。
   - 离线时「运行结果」**应如实提示** Python 需要联网（已加载过时可能仍能运行），**不应显示编造的输出**。
   - 离线时打开 `v1rc/privacy.html`：**应能打开**（隐私页在离线缓存里）。
5. 每一步记通过 / 失败、失败步骤、截图。
